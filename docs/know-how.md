# 再利用できる工夫とポイント

元の「情報ネットワーク 後期中間 対策ドリル」で効いていた工夫を、ほかの科目でも使えるように整理しました。
各項目に、テンプレートのどこで実装しているかを書いています。

---

## 1. 構成：データとエンジンを分ける

| 工夫 | 理由 | 実装 |
|---|---|---|
| 問題は**関数呼び出しの羅列**で書く（`mc(...)`, `fill(...)`） | JSON より短く書け、コメントや共通の前置き文（`const FIG = "…"; mc("7.1", FIG + "…")`）も使える | `src/drill.js` の `Drill.mc` など |
| `source("slide")` で以降の出典を**まとめて切り替える** | 1問ずつ出典を書かずに済む | `Drill.source` |
| 節・出典・形式の**3軸タグ**を全問題に付ける | 「この節だけ」「テスト対策だけ」「記述だけ」をすべて同じ絞り込み処理で扱える | `filterPool` |
| 用語集から**問題を自動生成**する（説明→用語の入力／4択） | 1行書けば2問増える。4択の誤答は**同じ節の用語**から選ぶので、紛らわしい選択肢になる | `buildPool` 内の `S.terms.forEach` |
| **ジェネレータ**で数値を毎回変える | 計算問題は数値を変えて繰り返すのがいちばん効く。答えの丸暗記を防ぐ | `Drill.generators`、ホームの「計算ドリル」 |
| 配布は**1ファイルHTML** | サーバ不要。スマホに送る、LMS に置く、オフラインで使う、のどれでも動く | `tools/build.mjs` |

## 2. 採点：表記ゆれに寛容にする

自由入力は、正しい答えなのに×になると一気にやる気が下がります。

- **正規化してから比較**：NFKC（全角/半角）→ 小文字 → ひらがなをカタカナに → 空白・中黒・括弧・長音・ハイフンを除去（`norm`）
- **コード入力の表記ゆれも吸収**：引用符の種類（`'` と `"`）・末尾の `;`・`!=` と `<>` を同一視する。空白と大小文字はもともと無視されるので、`update S set 在庫数=30 where 商品名="電卓"` も `UPDATE S SET 在庫数 = 30 WHERE 商品名 = '電卓';` と同じ扱いになる
- **括弧書きを無視**：「呼量（こりょう）」も「呼量」も正解（`stripParen`）
- **別解は配列で持つ**：`inp(ch, q, ["正解", "別解1", "別解2"])`
- **数値は許容誤差つき**：0.5% まで正解。カンマや単位を付けて入力しても数値だけ取り出す（`parseNum`, `numOk`）
- **逃げ道を用意する**：判定に漏れたときは「正解にする（表記ゆれ）」ボタンで自己判定できる
- 記述は機械採点しない。**模範解答＋キーワードの一致表示**を見せて、○△× で自己採点する

## 3. 出題：シャッフルの方針

| 対象 | 方針 |
|---|---|
| 問題の順番 | 既定はランダム。「資料の順」も選べる（テスト対策を上から解くとき用） |
| 4択の選択肢 | シャッフルする（「位置で覚える」のを防ぐ） |
| 2択（許可/拒否、同じ/別など） | シャッフルしない。順番が変わると押し間違えが増えるため。`{fixed:true}` で明示的に固定することもできる |
| 並べ替え・対応付け | 項目・右側の選択肢をシャッフルする。データは**正しい順**で書くだけでよい |

## 4. 学習の流れ：迷わせない

- **ホームに「すぐ始める」ボタンを並べる**：おまかせ／資料の問題を全部／用語／計算ドリル／記述／苦手復習。設定画面を開かなくても始められる
- **苦手復習＝「直近で間違えた」問題**：通算の正答率ではなく最後の結果で判定するので、一度正解すればリストから外れる
- **結果画面から「間違えた問題をもう一度」**：1回の演習の中で弱点をつぶせる
- **節ごとの進捗バー**：どこが手薄かがひと目でわかる。各行から直接その節を解ける
- まとめの各節の末尾に「この節の問題を解く →」を置き、**読む→解く**の往復を短くする

## 5. まとめ＋赤シート

- まとめ本文は HTML で書き、覚える語を `[[語]]` で囲むだけで赤字になる
- 赤シート ON の間は赤字が見えなくなる。**タップした語だけ表示**されるので、1語ずつ思い出してから確かめられる
- 用語集も同じ仕組みで、用語名を隠して説明から思い出す練習ができる
- まとめで使える部品：`note`（補足・覚え方）、`formula`（公式）、`<ol class="flow">`（番号付きの手順）

## 6. 認知負荷を下げる UI の決まりごと

- 状態は**文言ではなく見た目**で示す（赤シートはボタンの塗りで ON/OFF がわかる）
- **0件になる選択肢は出さない**（出典が1種類なら出典欄ごと隠す。0問になるホームボタンは出さない）
- 説明文は1行以内。操作説明は、その操作が必要な形式（並べ替え・計算）にだけ出す
- 判定はすぐ返す：選択式はタップした瞬間に判定し、正解を緑、選んだ誤答を赤にする
- キーボード：PC では 1〜9 で選択、Enter で「次の欄 → 答え合わせ → 次の問題」と進む
- 日本語 IME の変換確定の Enter で誤送信しない（`e.isComposing`）
- スマホ：タッチ端末では自動フォーカスしない（キーボードが急に出ないように）。計算欄は `inputmode="decimal"` にする

## 7. 保存とデータの安全

- 成績は `localStorage` に保存する（その端末のブラウザだけ。アカウント不要）。キーは科目ごとに `storageKey` で分ける
- 問題IDは**内容のハッシュ**にする。番号にすると、問題を1問挿入しただけで以降の成績がすべてずれる
- 成績リセットは2回押しで確定する（誤操作対策）
- `localStorage` が使えない環境（プライベートモードなど）でも落ちないよう、読み書きは try/catch で囲む

## 8. データ作成時の品質チェック

`npm run check` が次を検出します。AI に問題を作らせたあとにも必ず通してください。

- 正解番号が範囲外、選択肢の重複、空欄の正解漏れ、計算の答えが数値でない
- 対応付けの `ans` の長さ・範囲の誤り
- `sections` / `sources` にない節ID・出典ID（打ち間違い）
- **用語の説明に答えそのものが含まれている**（例：「IP Configuration の略」→ ipconfig）
- ジェネレータを30回まわして、例外や不正な問題が出ないか

## 9. 問題作りのコツ（データ側）

- 出典を分ける：**スライドの確認テスト／配布されたテスト対策／自作**。試験直前は前の2つだけ解く
- 用語の説明は「用語そのもの」を含めない。略語の由来はまとめ側に書く
- 状況つきの選択問題（「教室でスマホが…」）を混ぜる。定義の暗記だけでなく、当てはめの練習になる
- 共通の図や設定は定数にして問題文の先頭に付ける（`NETFIG + "…"`）
- 表を読ませる問題は、問題文に `|` 行で表を書く。共通の表は定数にして使い回す（`const T_R = "|#R\n|A|B\n|1|x"; mc("4.1", T_R + "\n…")`）。解説にも結果の表を書くと、答え合わせで見比べられる
- 解説（`exp`）は「なぜそうなるか」を1〜2文で。計算は途中式を書く
- 資料の誤植に気づいたら解説に `※スライドには「…」とあるが…` と書いておく
